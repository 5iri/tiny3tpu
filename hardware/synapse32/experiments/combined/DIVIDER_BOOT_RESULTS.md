`/tmp/tiny3tpu-divider-boot-md1k2qpe/`; separate board build:
`/tmp/tiny3tpu-divider-boot-md1k2qpe/build/`.

The runner called the unmodified `tools/kc705_open_build.py synth` using
`--cpu-overlay-dir hardware/synapse32/experiments/divider` and the isolated
`--build-dir`. Its local `--yosys` hook first asserted that the builder's script

Exactly one full-board Yosys synthesis and one route completed. Proof/mapping

## Equivalence and preservation evidence

Fresh boot-controller proofs passed for BOOT_WORDS 16384, 3, 32768, 1, 2,
536870912, 536870913, and 1073741824 using
`equiv_simple; equiv_induct -seq 4; equiv_status -assert`. The proof's candidate
hash exactly matches the frozen SoC overlay used in full synthesis. This is
the reviewed controller abstraction: requests, stalls, responses, and RAM
read data are arbitrary; RAM read/write controls, address, data, peripheral
side effects, and transaction outputs are compared without traffic assumptions.

The only SoC source change is boot address decode. Module parameters, boot
RAM initialization/processes, sequencer, clock enables, and transaction logic
are unchanged. Thus the bootdecode proof composes with the unchanged divider
CPU through the same request/response boundary, including its extra stalls.
It is not a full CPU/DDR sequential-equivalence or array-content proof.

The existing divider test harness was relocated to the temporary directory
without changing test semantics. Fresh results:

- 16,437 divider arithmetic checks, including 33 cancellation boundaries,
  operand capture, and exact normal/special latency.
- Continuous-clock and sequencer-clocked real CPU tests each passed 1,067
  divisions, 1,355 ordered stores, one data load, 1,068 launches (one canceled),
  1,067 retirements/writebacks, timer interrupt/MRET retry, and reset mid-divide.
- Full synthesis `check -assert` passed. Top ports match the divider baseline.
  All 16 RAMB36E1 and 124 RAM32M parameter/INIT dictionaries match by instance
  name. Flip-flop, DSP, clock, and I/O parameter/INIT multisets and counts match.

The divider changes instruction latency, so no cycle-by-cycle equivalence to
the original single-cycle divider is claimed. Its tests are dynamic evidence,
not an exhaustive ISA or interrupt/flush collision proof. During this run,
the divider owner added collision tests to `verify.sh`; no implementation
`.v` files changed. This run retained the already executed harness and its
original hash, and does not claim those newly added collision tests. Their
coverage/results remain the divider owner's evidence.

| Mapped resource | Divider-only | Divider + bootdecode |
| --- | ---: | ---: |
| LUT1..LUT6 | 15861 | 15829 |
| CARRY4 | 567 | 562 |
| Flip-flops | 13071 | 13071 |
| MUXF7 | 437 | 711 |
| MUXF8 | 170 | 241 |
| RAMB36E1 / RAM32M | 16 / 124 | 16 / 124 |

Whole-design remapping changed LUT/mux/carry usage; the five-carry delta is not
solely the four local boot comparator cells identified in the isolated proof.
Final system critical path starts at `soc.sequencer.state[0]`: approximately
18.7 ns, 2.0 ns logic / 16.7 ns routing. Final CPU critical path starts at
`soc.cpu.ex_mem_inst0_instr_id_out[3]`: approximately 26.4 ns, 8.1 ns logic /
18.3 ns routing. Parent worst paths differ, so these are not paired endpoint
measurements. Cross-clock max delays: system-to-CPU 7.18 ns; CPU-to-system
13.84 ns. None of these results establishes physical DDR or clock-gating signoff.
